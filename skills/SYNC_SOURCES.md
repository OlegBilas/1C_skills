# Синхронизация 1С-скилов

Этот каталог содержит локальные скилы из нескольких источников. Каталог не является Git-клоном, поэтому историю происхождения следует определять по комментариям `Source:` в скриптах скилов.

## Правила источников

- `# Source: https://github.com/Nikolay-Shirokov/cc-1c-skills` — обновлять только из этого репозитория; использовать Codex-сборку `port-codex` либо переносить изменения из `main` с адаптацией под Codex.
- `# Source: https://github.com/Desko77/claude-code-skills-1c` — обновлять только из этого репозитория и адаптировать Claude Code-специфичные инструкции, пути, команды и названия инструментов.
- Если в каталоге скила нет явного маркера источника, считать его локальным/неустановленного происхождения и не перезаписывать на основании совпадения функциональности или имени.
- Если один каталог содержит маркеры двух источников, синхронизировать только конкретные файлы, для которых источник указан; при неясном происхождении сохранять локальный файл и отмечать расхождение.
- Не заменять локальную Codex-адаптацию файлом для Claude Code. Сохранять `.codex/skills/...`, инструменты Codex и локальные доработки.
- Новые скилы добавлять отдельным каталогом с Codex-совместимым `SKILL.md`; не переносить платформенно-специфичные Claude Code скилы без адаптации.

## Еженедельная процедура

1. Сравнить локальный перечень с обоими upstream-репозиториями.
2. Просмотреть изменения только для файлов с подтвержденным маркером соответствующего источника.
3. Для совпадающей функциональности обновлять только скил, происходящий из этого репозитория; не менять локальный скил другого происхождения.
4. Добавить отсутствующие полезные скилы после адаптации под Codex.
5. Упаковать весь каталог `skills` в `D:\mcp-servers\skills(Широков+Desko77).zip`.
6. Сообщить пользователю о примененных обновлениях и созданном ZIP. Если upstream не изменился — ZIP повторно не собирать и не отправлять сообщение об обновлении скилов.
